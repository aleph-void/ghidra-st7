# ST7: verification notes (Ghidra-Rare)

Languages `ST7:BE:16:default` and `ST72:BE:16:default` (see README.md). Provenance and the list of
changes are in [CREDITS.md](CREDITS.md). Everything below is reproduced by `test/run-tests.sh
[--real] <workdir>` (needs `asl` = AS 1.42 on PATH; `UCSIM_ST7` = the uCsim ST7 simulator built by
`test/build-ucsim.sh`, optional). Run against Ghidra 12.1.4; the release zips also build for 12.1.3
and 12.2 (the specs are compiled with each version's SLEIGH compiler).

## Method

- **Decode.** AS is an assembler, not a disassembler, so the comparison is a round trip: every
  statement is assembled by asl, the bytes decoded by Ghidra, the text assembled again. The
  manual's opcode tables (PM0002 section 4) and the uCsim disassembler are two further opinions.
  SDCC has no ST7 port (it has STM8, a different instruction set) and MAME has no ST7.
- **Semantics.** Three implementations: Ghidra p-code, `test/st7model.py` (written from the
  manual's operation/flag/stack tables) and the uCsim simulator. `test/sem_diff.py` runs random
  single instructions on all three; Ghidra must equal the model, and every disagreement with
  uCsim must fall in a class below (otherwise the run fails). The hand-written emulator cases
  (`test/emu/cases-hand.txt`, plus the conditional branches generated by `gen_branch_cases.py`)
  are separate and were worked out from the manual.
- **Real code.** `test/fetch-samples.sh` fetches the firmware (pinned commit and SHA-256 of
  [DCRabbit_9](https://github.com/digidotcom/DCRabbit_9), `RabbitNet HW/ST7microcode`); nothing
  is committed.

## Confirmed reference-tool defects

uCsim `ucsim_st7` (an STM8 simulator adapted to ST7), checked against PM0002:

- Disassembly: `LD (X),X`/`(short,X),X`/`(long,X),X` printed with Y as the source; `SWAP X`
  printed as `swapw`; `CP X,#imm` treated as a 16-bit immediate; `CP X,[short]` and
  `([short],X)` printed as `.w`; `CALL [long.w]` printed as `[short]`; `CALL [short]` and
  `CALL ([short],X)` (92 BD / 92 ED) not decoded; the 91-prefixed Y forms of LD get the wrong
  length; `btjf` printed as `bjtf`.
- Semantics: `LD` in all forms leaves N and Z unchanged; the shifts, rotates, `NEG`, `SWAP`, `TNZ` do
  not update N; `BTJT`/`BTJF` do not copy the tested bit into C; `NEG` of 0 sets C; `MUL` leaves H
  and C; `JP` (all modes, including `jp $1234`) jumps to the byte stored at the target; the
  92-prefixed (indirect) `BSET`/`BRES`/`BTJx` ignore the pointer; `TRAP` is not implemented;
  `LD S,r` clears the high byte of SP; `PUSH CC` omits bits 7-5; the PC does not wrap at 64 KB;
  its X/Y registers are 16 bits wide (STM8 heritage) and are mixed in the Y forms of
  `RLC/RRC/SLL/SRA/SWAP/TNZ/NEG/BCP`; `JRNM`/`JRM` have no `I1`.
- No asl defect against the manual was found.

## Doesn't work

| Gap | Why |
|---|---|
| `HALT` and `WFI` are userops (after clearing the interrupt mask) | oscillator/CPU stop state is hardware state; the emulator cannot run them |
| Interrupt entry is not modelled (no automatic push of the context, no vector fetch); `TRAP` is modelled | interrupts are asynchronous hardware events; handlers are found through the vector analyzer, and `IRET` restores the context |
| Stack-pointer limits: the 6 low bits of SP wrap on 64-level devices, and the high byte is fixed by the device | device dependent (0x00 on 64-level parts, 0x01 on 256-level parts); `RSP` sets only the low byte so the device's high byte survives |
| Peripheral registers and I/O ports are plain memory; `EXTI` (for `JRIH`/`JRIL`) is a free-standing register | hardware state |
| Vector table size is guessed (0xFFE0-0xFFFF, stops at the first entry that does not look like a vector); stack dispatch tables stop at the first entry that is not a code address (at most 128) | the count of vectors/entries is device and program specific; false positives are possible on 6-vector devices whose lowest table entries are followed by code |
| No `.dwarf` register mapping; the compiler spec (arguments in X then A) is a guess | no ST7 compiler was available to observe either |

## Unverified

- The two-bit-priority variant (`ST72`): PM0002 describes only the single mask bit `I`, so
  `I1`/`I0` (`SIM` sets both, `RIM` clears `I0` and sets `I1`, `JRM` = both set, `JRNM` = both
  clear, `TRAP` sets both) follow the upstream definition; no document we hold describes them.
- Whether `LD S,r`/`LD r,S` and the register-to-register `LD`s update N and Z (the manual's
  summary table says LD affects N and Z; assumed for all forms).
- CC bits 7-5 read as 1 (the manual's figure shows `111HINZC`); not observable without hardware.
- The ELF opinion (`e_machine` 68): no ST7 ELF file was available.
- Any ST7 device other than the ST72264 firmware above; hardware behaviour.
